Dodoma

A macOS menu-bar app that notices when you typed Arabic on the English layout — or the reverse — and rewrites it in place, switching the keyboard as it goes.

13 SLIDES · HOW IT WORKS · v1.0.0
00The Problem

You never forget the language. You forget the layout.

Writing in two languages means switching input source dozens of times a day. The switch back is the one that gets missed — and nothing warns you until a whole sentence is already on screen as nonsense.

hgsghl ugdj
what appeared
Arabic typed while the US layout was active.
السلام عليك
what was meant
Every key pressed was already the correct key.

The old fix is manual and identical every time: select, delete, switch layout, retype. A dozen times a day, that interrupts the thought you were actually having.

01The Key Idea

Record the key, not the letter.

The letters on screen are the wrong evidence — they are already the mistake. The physical key you pressed is the same key in both layouts, so your intent is recoverable exactly, with no guessing.

What Dodoma stores KEYCODE
Key 4, key 1, key 5… physical positions, layout-independent. Plus the modifier state and what the key actually produced.
Rendered as English
h · s · g

Meaningless in English. No dictionary hit, impossible letter pairs.
Rendered as Arabic
ا · س · ل

Real words. That gap is the entire signal.

Both renderings come from macOS's own uchr layout tables — not a hand-written substitution map — so shifted keys, Caps Lock and the Arabic لا ligature all come out right.

02The Pipeline

Six stages, one second.

Nothing happens while you are still typing. The whole chain fires on the pause.

keystroke → buffer → pause → render ×2 → score → decide → apply

04Stage 2 — Render Twice

The same keys, read through two alphabets.

After one second of quiet, the buffered keycodes go through UCKeyTranslate against each enabled layout's real table. Modifier handling is tried three ways, because Caps Lock and Shift are not the same thing in Arabic.

Cap modeWhy it existsResult for the canonical sample
as typedExactly the modifiers you held.آئ ؤءك… — diacritic junk
shift strippedCaps Lock on is the most common way this mistake happens.اذ ودك انا اسويها اليوم
lowercasedShift and Caps both dropped.اذ ودك انا اسويها اليوم

The best-scoring of the three wins. This is also why no key table is hard-coded: the Mac Arabic layout differs from the Windows one (c=ذ v=د m=و), and Dodoma reads whichever layouts you actually have enabled.

05Stage 3 — Score

Two numbers decide it — both computed on your Mac.

There is no model call and no network code anywhere in the app. Each rendering is scored against bundled frequency data for its language.

score = 0.55 × bigram + 0.45 × dictCoverage # bigram how plausible the letter # pairs are in that language # dictCoverage share of letters inside # real dictionary words

Arabic lookups strip harakat and clitics (و ف ب ل ال); English strips s / ed / ing / 's. Data: OpenSubtitles frequency lists, ~40k words per language.

06Stage 4 — Decide

Three outcomes, and most of the time it does nothing.

A high score is not enough on its own. The region has to be long enough, and every guard has to stay quiet.

Rewrite CLEAR WIN
Alternate ≥ 0.62, current ≤ 0.28, gap ≥ 0.40, ≥ 6 letters, no guard fired. Happens silently.
Suggest BORDERLINE
A card near the caret. Tab or click accepts, Esc or typing dismisses, gone after 4 s.
Ignore DEFAULT
Everything else. Normal writing in either language never triggers anything.

Guards that veto a rewrite outright: URLs, paths, emails, digits touching letters, camelCase and snake_case, single short tokens, mixed scripts inside one word, and anything you just undid.

Only the trailing run is ever rewritten — so check this hgsghl touches the last word only, and a genuinely bilingual sentence is left alone.

07Stage 5 — Safety

It is about to delete your text.

Everything above only decides what to do. These gates decide whether it is allowed to happen at all — each one can only ever cancel the fix, never cause one.

Policy
per app
Terminals suggest only. Password managers off entirely. Any app can be set to Normal / Suggest / Off.
Secure
password fields
Secure input and AX secure fields drop the buffer and purge the keystroke log.
Verify
before deleting
The app is asked what sits in front of the caret. No match, no answer — downgrade to a suggestion.
Focus
every event
The frontmost app is re-checked before each injected keystroke, so a ⌘-Tab mid-burst aborts it.

If you type anything while a fix is being decided, it is abandoned — the record no longer matches the screen, and a stale record is exactly how a tool like this corrupts text.

08Stage 6 — Apply

Delete, type, switch — in about 160 ms.

macOS has no "reinterpret that text" call, so the fix is performed the only way it can be: by pressing keys, very fast, on your behalf.

#StepPaceWhy
1Backspace, once per character3 msWas 10 ms — a 23-character fix spent half a second visibly erasing itself.
2Settle15 msLet the app catch up before text arrives.
3Inject the corrected text2 msUp to 60 characters per event — effectively one shot.
4Switch the input sourcelastAfter the text lands, so the app's IME cannot interfere mid-insert.

Injected keystrokes are stamped with a marker so Dodoma ignores its own typing — otherwise the fix would be detected as new input and fixed again, forever.

09When It Is Wrong

One key puts it back.

A tool that edits your text without asking needs an exit that works even when everything else is jammed. The hotkeys are registered with Carbon, outside the event tap, so they respond even if the tap itself has stalled.

⌥⌘Z 30 s
Restores exactly what you typed, switches the layout back, and suppresses re-fixing that text for 60 s so it cannot bounce.
⌥⌘P PAUSE
Stops all rewriting instantly, everywhere. The tap keeps running; nothing is evaluated.
Per-app SETTINGS
Set any app to Suggest-only or Off. Terminals and password managers already default that way.

The undo is withdrawn the moment you move on — a click, Return, or switching app — because reverting into text you have since edited would do more damage than the original mistake.

10What Live Testing Changed

Two things only real use could find.

Both passed every unit test and both were obvious within minutes of typing in real apps.

The single-letter wall FIXED

"how i did what" came back as:

اخص ه did what

The search for where the mistake began stopped at any word the other layout did not clearly improve — and a one-letter word scores the same in both languages. The lone "i" tied, became a wall, and stranded everything before it. Single letters are now transparent.
Watching it type FIXED
The replacement was correct but visible — half a second of erasing one character at a time, during which your own keystrokes were dropped. It read as the machine seizing up mid-sentence.
  • 512 ms → 157 ms for the same fix
  • Dropped-input window 300 ms → 120 ms

Deleting stays at 3 ms rather than 0 on purpose: some apps silently swallow keystrokes that arrive too fast, and a swallowed delete leaves garbage behind — worse than being slightly slow.
